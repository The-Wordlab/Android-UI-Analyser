How it works

Three calls an agent can understand

A screenshot is expensive for an agent to read and still leaves it guessing where to tap. AUA hands it the screen as data.

01 · SEE

Every element, with an ID

Text, type, position and a stable ID for each control. Read from the accessibility tree or the DOM in tens of milliseconds, with OCR and vision for screens that have none.

aua --format compact analyze
02 · ACT

Tap and type by ID

The agent names the element. AUA finds it on the current screen, acts, and returns the screen that follows in the same call.

aua tap-and-analyze <id>
aua input-and-analyze <id> "hello"
03 · PROVE

Evidence, not a claim

Screenshots, screen recordings with the waiting cut out, and a report the agent builds from the run. The recordings on this page were made that way.

aua wait-and-analyze --for "Saved"

Closing the loop

Find the crash, then prove the fix

An agent that can use the app can do more than tick boxes. Here it tested a new character carousel on Android, hit a crash nobody could trigger on purpose, and came back to prove the fix.

01 · DRIVE

8 scenarios

Swipes both ways, opening a chat from a card, rotating the phone, pressing Back in the middle of an animation. 7 passed.

02 · CATCH

Two crashes while idle

The app closed twice while nothing was being touched. The agent could not repeat it on demand, so it read the crash from the device and named a suspect: the tilt effect receiving a value that is not a number.

03 · FIX

A fix goes in

The finding went to the pull request with the recording and the crash, and the code was changed.

04 · PROVE

Old build closes, new one holds

The agent made the emulator's motion sensor report "not a number". The old build closed at once. The fixed build kept drawing for 60 seconds, and stayed up through four idle waits of 60 to 130 seconds.

What your agent gets

Built for agents, usable by people

The same commands work in a terminal and over MCP, on all three platforms.

Android, iOS simulator, web

Android devices and emulators from Android 7.0, iOS simulators on macOS, and Chromium, Firefox and WebKit through Playwright.

IDs that survive a redraw

An element keeps its ID while the screen changes around it, so the agent can keep acting without looking again.

The result comes back with the action

Every tap, type and swipe returns the screen that followed. No second call to see what happened.

Wait on state, not on time

Wait for text to appear or the screen to change instead of sleeping and hoping.

Saved flows and known routes

Replay a journey in one call, and jump to a screen the tool has already learned how to reach.

Evidence built in

Screenshots, recordings, logs and a report page, so a person can check what the agent says it did.

Install

Try it in one line

You need uv. For Android you also need adb and a device or emulator.

Run it without installing

uvx aua doctor
uvx aua --format compact analyze

Claude Code plugin

/plugin marketplace add The-Wordlab/Android-UI-Analyser
/plugin install android-ui-analyser@the-wordlab

Codex plugin

codex plugin marketplace add The-Wordlab/Android-UI-Analyser
codex plugin add android-ui-analyser@the-wordlab

Any MCP client
